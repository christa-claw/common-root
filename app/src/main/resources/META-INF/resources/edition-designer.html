What each control actually costs

  1. Type size is the biggest lever on extent, bigger than margin. On the standard trim, 7.5 pt sets in 749 pages and 10.5 pt in 1,485 — a large-print edition is twice the book. Measured
  2. Format barely changes the page count, because each trim's type size scales with the page. A pocket Bible is a smaller object, not a longer one.
  3. The two-column setting has a boundary that moves. Wide margins and large type both squeeze the column; below about 28 characters a line, justification opens rivers. At 8.8 pt the columns survive to a 38 mm fore-edge; at 10.5 pt they give out at 24 mm and the book becomes a single-column reader's edition.
  4. Apocrypha adds about 22% — 6,736 verses against 31,103. In traditional order their placement is conventional; in chronological order it still needs building.
  5. Colour changes the job, not just the look. Any accent but black means two inks and a requote.
  6. The spread is the unit, not the page. With the head split, the verso names the book and the recto names the chapters, so nothing is said twice and each side answers one question. On a page that opens a book there is no head at all — the rule beneath already names it.
  7. The traditional titles assert things the books do not. “The Epistle of Paul the Apostle to the Hebrews” names an author the letter never names; so do the five books of Moses, the Lamentations of Jeremiah and the Saints before the evangelists. That sits oddly in an edition whose argument is that chapters (1227) and verses (1551) are later additions worth showing as such — so it is a setting, and Name only asserts nothing. The long title is also English-only: a Finnish or German edition gets the bare name until someone supplies the titles.

How an order would work Proposal

  1. The reader chooses and saves an order. On this page they pick an edition and press Create print order (below the spec). They get a small file, an example of which is below. It carries our reference and a spec id: the same spec id is the same interior, so identical orders can be grouped into one print run. The page would offer a fixed set of editions, because every different interior is its own set-up.
  2. The reader sends it to Pretore. Pretore bills them and ships the book. The price is Pretore's: the figures on this page are estimates, not quotes.
  3. Pretore sends us the file with its own order number.
  4. We build the print-ready package from it, in about ten seconds: build_package.py --order file.json --order-id <Pretore's number>. It holds the interior PDF, the rights page, the spec and the font licences, stamped with both numbers. A file edited after it was made no longer matches its spec id and is refused.
  5. We send the package to Pretore, who print and ship.

Not yet agreed: whether Pretore will bill and ship to individual readers, the smallest run of identical orders, what is needed for the cover, and how orders should reach Pretore.

Why a reader does not see this page

All of it lives inside the PDF, so changing any of it means re-typesetting — and a different interior is a separate setup at €750, not a share of a €775 batch. Twenty-five readers choosing twenty-five margins would cost €18,750. So this is the page that opens an edition; readers then join the one they like, and every copy in a run is identical. That is the whole reason the per-copy figure is €31.

Where the numbers come from

Extents marked Measured were typeset at that exact geometry and their pages counted; everything else is interpolated between measured points and marked Derived. The baseline is a full run: the WEB in event order, 66 books, on the standard trim at 8.8 pt, is 1,023 pages (31,103 verses). Cross references and the one-column reference edition are anchored to full runs of their own (1,166 and 1,223 pages), and scaled from there. Spine assumes 0.048 mm a leaf including binding bulk — an estimate to quote, not to cut a cover to. Prices are Pretore's for 1 and 25 copies; everything between is a straight line. Shipping excluded.
